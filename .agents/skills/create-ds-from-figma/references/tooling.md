# Operaciones auxiliares del kit

Consulta solo el apartado de la operación necesaria. Los contratos de evidencia, ficha y tokens permanecen en sus referencias canónicas; este archivo conserva operaciones que antes solo documentaba el README.

## Exportar vectores originales

La exportación original o la aproximación aprobada es una obligación del agente: los checks actuales no vinculan el SVG exportado con el código ni detectan por sí solos una reconstrucción CSS. No se presenta como una garantía automática de fidelidad.

Un nodo vectorial de Figma no se reconstruye con cuadrados rotados y bordes CSS: su forma, su trazo y su color se pierden sin que ninguna comprobación de geometría lo vea. `verification-plan.mjs requirements SNAPSHOT` lista como `vectors` los nodos VECTOR, BOOLEAN_OPERATION, STAR, POLYGON y LINE observados (candidatos sin clasificar, no recursos que haya que autorizar) y propone `EXPORT_VECTOR_SOURCES`.

```sh
node .agents/skills/create-ds-from-figma/scripts/figma-vectors.mjs capture FILE_KEY NODE_ID CONFIG --approve-connection
node .agents/skills/create-ds-from-figma/scripts/figma-vectors.mjs save SESSION EXPORT.json
node .agents/skills/create-ds-from-figma/scripts/figma-vectors.mjs svg EXPORT.json VECTOR_ID RUTA.svg
```

`capture` usa la misma conexión MCP autorizada que el resto (también existe `bridge FILE_KEY NODE_ID` para el adaptador de Codex) y transfiere el SVG exacto de `exportAsync` por bloques comprobados, sin transcripción. El sobre sellado guarda el SVG, las cajas de maquetación (`bounds`) y de renderizado (`renderBounds`): el SVG exportado se recorta a lo que el nodo dibuja, así que `renderBounds` es lo que lo coloca respecto a la raíz, no `bounds`. `svg` escribe el archivo tal cual y nunca sobrescribe. El SVG se analiza con un parser XML estricto (`saxes`): se rechaza lo mal formado o incompleto, un DOCTYPE, entidades, CDATA o instrucciones de proceso, un elemento fuera del espacio de nombres SVG y los elementos que ejecutan, cargan o estilan contenido (`script`, `style`, `foreignObject`, `iframe`, `a`, animaciones...). Los valores de atributo se restringen por gramática y no por búsqueda de palabras: no pueden llevar barras invertidas, comentarios ni `@` (así los escapes CSS como `u\72l(` o `@im\70 ort` no tienen dónde esconderse), solo pueden usar las funciones que escribe el exportador (`url`, `rgb`, `rgba`, `hsl`, `hsla`, `matrix`, `translate`, `rotate`, `scale`, `skewX`, `skewY`; `image-set()` y similares se rechazan), `url()`, `href`, `xlink:href` y `src` solo pueden apuntar a un fragmento local `#id` o a una imagen raster `data:` en línea, `style` se limita a las propiedades que emite Figma, y de los atributos con espacio de nombres solo se admiten `xlink:href`, `xml:space` y `xml:lang` (`xml:base` redirigiría las referencias). También se acotan elementos y profundidad. No es un sanitizador: rechaza lo que el exportador de Figma nunca emite, de modo que lo que pasa es inerte como `<img>` o archivo y no contiene contenido activo ni externo en lo que se comprueba, pero insertarlo en línea en la página exige revisarlo o reconstruirlo desde un DOM filtrado. Es el SVG original, no una autorización ni una equivalencia CSS ni una prueba de fidelidad renderizada: usarlo como archivo del proyecto requiere la misma aprobación que cualquier recurso, y aproximar la forma con CSS es una decisión explícita que debe revisarse con la comparación visual. La integración con Figma real se comprobó leyendo un componente con el colector exacto (dos vectores con su `renderBounds`); el cliente MCP directo y Claude Code siguen sin validar.

En el sobre de vectores, `capturedAt` exige una cadena ISO UTC canónica de `toISOString()`, con milisegundos y fecha válida, tanto al sellar como al leer. Fecha el sellado, no una revisión de Figma. SHA-256 cubre solo el contenido canónico de `vectorExport`, no la fecha: verifica integridad, no autenticidad ni momento de captura. La declaración XML `<?xml version="1.0"?>` se admite; no es una instrucción de procesamiento como `<?xml-stylesheet?>`, que sí se rechaza.

## Residuo de píxeles experimental

`node .agents/skills/create-ds-from-figma/scripts/pixel-diagnose.mjs compare REFERENCIA.png CANDIDATO.png REGIONES.json [--max-shift N] [--heatmap SALIDA.png]` compara, región a región, un PNG de Figma con una captura del componente y ordena las regiones por lo que se parecen menos. `REGIONES.json` es una lista de `{ id, x, y, width, height }` en píxeles enteros de la imagen de referencia, normalmente las cajas de las partes que no son texto. Cada región se alinea por separado (hasta `--max-shift` píxeles, 12 por defecto) para cancelar la desviación geométrica, que ya informan los checks de geometría, y conserva el residuo de aspecto: diferencia media y porcentaje de píxeles con diferencia fuerte (más del 8 % del rango). Lo que el candidato no cubre cuenta como diferencia total, nunca como papel blanco, y `coveragePercent` indica qué parte de la región cae dentro del candidato en el desplazamiento elegido; así un candidato totalmente distinto, recortado o desplazado fuera de la imagen no puede parecer una coincidencia. `--heatmap` escribe un PNG con las diferencias en rojo y nunca sobrescribe.

Es un aviso, no una comprobación: el resultado es siempre `NOT VERIFIED`, no calibra umbrales y no está conectado a `--diagnose` ni al cierre. El coste de la búsqueda (píxeles de las regiones por (2·maxShift+1)² comparaciones) se calcula antes de empezar y se rechaza si supera `--max-operations` (250 millones por defecto, máximo 4000 millones), con un tope de 256 regiones e imágenes de hasta 8 megapíxeles y 16384 píxeles por lado. La cabecera del PNG se lee antes de descomprimir nada, de modo que un archivo pequeño que declare dimensiones enormes se rechaza sin reservar memoria, y los PNG entrelazados no se admiten porque su descompresión no se puede acotar; la búsqueda descarta pronto los desplazamientos que ya no pueden ganar, sin cambiar el resultado, y `--heatmap` estima la alineación en una ventana central de hasta 256×256 en lugar de en toda la imagen. Ordena regiones por su residuo; `hotspots` marca las que superan el 2 % de píxeles fuertes y, si hay al menos dos regiones más, triplican la mediana de las demás. Sirve para que un modelo que no ve imágenes pueda leer "esta región difiere" y para localizar defectos que la geometría no ve, como el contorno ausente de un pico. Límites: el suavizado de aristas rotadas deja un suelo (una corrección buena sigue apareciendo como la región más alta, con un residuo bastante menor), el texto y las sombras difieren entre renderizadores, y las dos imágenes deben estar a la misma escala. La exportación `node-bounds` de `figma-reference.mjs` recorta lo que sobresale de la caja (un pico, una sombra); para comparar eso hace falta una exportación con los límites de renderizado, que el kit no genera todavía.

Medido sobre el pico de un Tooltip real a 4×: región del pico 8,5 % de píxeles fuertes (18 veces las demás) con el defecto y 2,9 % (7 veces) corregido; bordes y esquina por debajo del 0,2 % tras alinear. Una sola muestra.

## Ejecutar pruebas y mutaciones

La salida termina con KIT SUMMARY por perfil y TOTAL REPORTED acumulado, obtenido de los eventos estructurados del runner de Node (incluidos subtests), no del último bloque TAP. Si las unitarias fallan, browser figura NOT RUN; los perfiles no solicitados figuran NOT REQUESTED. Si falta un resumen se indica que no hay contadores disponibles y nunca se presenta una ejecución completa como correcta.

`npm run test:resources:mutations` ejecuta mutaciones dirigidas en una copia temporal, sin alterar el checkout. Primero exige que pasen las pruebas sin mutar y después comprueba que estas rechacen cambios de hash, cobertura, sustitución, alcance de escritura, acciones y enlaces de fuentes. Guarda el resumen en `test-results/resource-mutations.json` (ignorado por Git) y falla ante supervivientes o errores de infraestructura. Es una selección explícita, no una puntuación de cobertura exhaustiva ni una prueba contra Figma real; no sustituye `npm test`.

Las regresiones reproducibles usan fixtures sintéticos versionados: comprueban que una geometría defectuosa, correspondencias candidatas o literales inválidos en la demo impiden la entrega. No dependen de ramas locales de prueba ni demuestran fidelidad contra Figma real.

El conjunto versionado contiene solo datos sintéticos: el [inventario sellado de prueba](../../../checks/tests/fixtures/variable-inventory-sealed.json) se regenera con `node .agents/checks/tests/fixtures/generate-variable-inventory.mjs`, a partir del mock y con fecha fija. Los PNG se generan durante los tests y no incluyen recursos de ningún diseño. Las capturas reales de experimentación se mantienen fuera del repositorio y no se presentan como evidencia reproducible aquí. npm test comprueba el mock, el fixture, la derivación y servidores de prueba; no acredita una conexión viva de Codex/Claude Code, el cliente directo contra Figma ni fidelidad visual.

`npm run test:diagnosis:mutations` comprueba la ausencia de partes, la separación entre diferencias y bloqueos de comportamiento y la procedencia de imágenes con la misma garantía de base sin mutar, copia temporal y fallos de aserción observables. `npm run test:inventory:mutations` comprueba fallos deliberados de integridad/origen, omisión de variables y modos, clasificación local/remota, elección arbitraria de modo, conservación de decisiones/registros y resolución de anidados por identidad. Ejecuta primero una base sin mutar y después cada cambio por separado en una copia temporal; no modifica el checkout. Un superviviente, error de sintaxis, timeout o fallo de infraestructura devuelve error. El informe queda en test-results/inventory-mutations.json, ignorado por Git. Es cobertura dirigida, no una garantía exhaustiva; `npm run test:resources:mutations` mantiene su alcance independiente sobre recursos y CSS. Ambos usan el mismo ejecutor.

`npm run test:delegation:mutations` comprueba regresiones deliberadas de detección, omisión, revisiones específicas y caducidad con fixtures sintéticos; no acredita fidelidad real ni sustituye `npm test`.
