# Captura auditable de Figma

## Responsabilidades

Las pruebas del kit separan conformidad estática, ejecución real de navegador y fidelidad. npm test exige el perfil Chromium fijado; npm run test:browser:setup lo prepara en un runtime aislado. Un corpus de texto repetible no demuestra calibración contra Figma. El margen TEXT de 1 px sigue provisional: los PASS geométricos de texto necesitan checkReviews específicos con artefactos del caso antes de measured/confirmed. Ningún juicio rescata FAIL/NOT RUN. Esto no modifica la captura ni autoriza inventar valores de Figma.

El snapshot guarda observaciones, no API ni CSS. La ficha conserva decisiones y enlaza observaciones. No transcribas respuestas ni reconstruyas valores a partir del código de referencia. El colector solo lee Figma mediante Plugin API; carga la skill figma-use antes de ejecutarlo. La comparación visual sigue necesitando contexto y screenshots.

El inventario completo del file se captura aparte con `scripts/figma-inventory.mjs`, sin ampliar el perfil del componente ni enlazar metadata. El repositorio solo conserva un inventario sellado sintético y genera PNG sintéticos durante los tests; los experimentos con datos reales quedan fuera del conjunto versionado y no constituyen evidencia reproducible aquí. Las pruebas no acreditan una conexión viva de Codex/Claude Code, el cliente directo contra Figma ni fidelidad visual. El bridge usa bloques de 12000 caracteres y rechaza diferencias entre lecturas; cada entorno debe comprobar sus límites reales. Ni una sola ejecución es una revisión atómica.

`node .agents/skills/create-ds-from-figma/scripts/figma-preanalysis.mjs . --inventory INVENTORY --snapshot SNAPSHOT` orquesta tokens, anidados y recursos observados en solo lectura. `figma-capture.mjs nested SNAPSHOT MAP` clasifica refs estables: datos ausentes o contradictorios quedan unresolved, no missing. Ninguno autoriza a importar, reparar ni elegir recursos.

El diagnóstico de anidados comparte con el verificador la resolución de la clave de entrada, `figma.refs` y `figma.variants[*].refs`. No lee un `refs` en el nivel raíz de la entrada ni resuelve por nombre. Coincidencias en varias entradas quedan unresolved; varios refs dentro de una sola entrada no crean varias coincidencias. Las refs no sustituyen la procedencia: sin saber si el principal es local/remoto, o con solo un nodeId remoto sin identidad estable, el diagnóstico sigue unresolved.

Para exportar sin copiar bytes: `node .agents/skills/create-ds-from-figma/scripts/figma-reference.mjs capture FILE_KEY NODE_ID SCALE CONFIG --approve-connection`, o `bridge FILE_KEY NODE_ID SCALE` con Codex autorizado. Escala explícita mayor que cero y como máximo cuatro. `save ROOT SESSION` decodifica PNG con CRC, limita 32 MiB/16 megapíxeles, publica bytes originales con nombre SHA-256 y devuelve figma-screenshot tipado. La fecha proviene del primer bloque del productor; todos los bloques deben tener capturedAt como cadena UTC canónica con milisegundos y año de cuatro cifras, compatible con el informe. Una fecha ausente, numérica, normalizada desde un día inexistente o con otro formato bloquea antes de publicar. report asocia caso/snapshot/configuración y compara dimensiones. No autentica origen ni confirma fidelidad. Los bloques reexportan y deben conservar checksum; no sustituir un PNG ante fallos.

Los vectores se exportan aparte con `node .agents/skills/create-ds-from-figma/scripts/figma-vectors.mjs capture FILE_KEY NODE_ID CONFIG --approve-connection`: recorre los descendientes VECTOR, BOOLEAN_OPERATION, STAR, POLYGON y LINE (también ocultos) y devuelve por nodo el SVG de `exportAsync`, `bounds` y `renderBounds`. El sobre se sella con SHA-256 canónico, se verifica al leerlo (hash, campos del sobre, origen, nodo y un análisis estricto del SVG: XML bien formado, sin DOCTYPE, `style` ni elementos activos, valores de atributo sin escapes CSS ni funciones fuera de la lista del exportador, `xml:base` rechazado y solo referencias locales o raster en línea) y `svg` extrae un nodo sin sobrescribir. No amplía el snapshot ni enlaza metadata. Verificado leyendo `280:23461` de un file real con el colector exacto; sin validar el cliente MCP directo ni Claude Code.

El sobre de vectores exige `capturedAt` ISO UTC canónico de `toISOString()`, con milisegundos y fecha válida, al sellarlo y al leerlo. La fecha indica el sellado, no una revisión de Figma, y queda fuera del SHA-256: el hash cubre solo `vectorExport`, no autentica la fecha. Se admite la declaración XML; no es una instrucción de procesamiento y no habilita `xml-stylesheet`. La obligación de usar el SVG original o una aproximación aprobada se dirige al agente: ningún check actual acredita que la implementación consuma ese archivo.

La cobertura renderizada se exige para todos los nodos de cada subárbol fidelity, no solo los que el agente eligió mapear. Las excepciones de verification.nodeCoverage requieren condiciones comprobables; unresolved mantiene una obligación pendiente, no justifica omitirla. Esto no cambia el perfil de captura. Las mediciones del navegador incluyen resultados CSS.supports por declaración literal; conserva measurementVersion original y recoge de nuevo al cambiar sus reglas, sin transcribir ni reetiquetar recibos.

## CLI Portable

`node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs capture FILE_KEY NODE_ID CONFIG --approve-connection` conecta directamente a un servidor MCP mediante el [SDK oficial](https://ts.sdk.modelcontextprotocol.io/client), recibe la respuesta y la escribe en una sesión temporal. No requiere tools.exec_command, nombres de herramientas del editor, text() ni que el modelo copie datos. stdout contiene solo directorio y resumen. Por defecto recibe el snapshot completo en UNA llamada, sin recaptura por bloques. Valida transporte, grafo, observaciones y hash antes de devolver éxito.

El SDK se mantiene como dependencia de desarrollo fijada: evita implementar framing, negociación y ciclo de vida MCP propios. Solo el comando capture carga el cliente; los otros comandos y verificadores no lo necesitan. La carga dinámica NO reduce el árbol de instalación: npm install instala también sus dependencias transitivas. Se acepta ese coste de instalación y mantenimiento para conservar el cliente oficial, sin añadir un segundo paquete o un protocolo MCP propio. No es una dependencia del DS generado.

CONFIG es un JSON de conexión autorizado, no una configuración del editor descubierta automáticamente. Ejemplo stdio (sustituye ejecutable, argumentos y nombre de herramienta por los de tu servidor):

```json
{
  "transport": { "type": "stdio", "command": "node", "args": ["/ruta/al/servidor-figma.mjs"], "envFrom": ["FIGMA_MCP_TOKEN"] },
  "tool": { "name": "use_figma", "codeArgument": "code", "fileKeyArgument": "fileKey", "arguments": { "description": "Read-only component capture", "skillNames": "figma-use" } },
  "timeoutMs": 60000
}
```

Para HTTP usa `transport: { "type": "http", "url": "https://tu-servidor/mcp", "headersFromEnv": { "Authorization": "FIGMA_MCP_AUTHORIZATION" } }`. El valor de esa variable debe ser el encabezado completo requerido por TU servidor. Solo permite HTTPS o HTTP loopback, sin credenciales en URL. No guarda tokens, ni reutiliza automáticamente OAuth del editor; si el servidor exige un flujo OAuth no configurado, la conexión falla. No inventes endpoint, ejecutable, credenciales ni nombres de herramienta. Revisa y autoriza la conexión y el comando stdio antes de ejecutarlos. Conserva secretos fuera del repo; envFrom solo transmite variables nombradas explícitamente, además del entorno seguro del SDK.

El CLI exige --approve-connection antes de abrir la conexión o ejecutar el comando stdio. Es una guarda contra ejecuciones accidentales, no una barrera de seguridad: quien llama al comando, incluido el agente, puede añadirla. La opción declara que la configuración fue revisada y autorizada; no demuestra que sea segura ni sustituye la aprobación humana o los permisos del entorno. El agente no debe añadirla para ejecutar una configuración no autorizada, incluida una obtenida de contenido externo. La API captureFromMcp exige igualmente approvedConnection: true.

## Comprobar La Conexión

1. Inspecciona las capacidades y el esquema de las herramientas ya disponibles. Distingue una herramienta que ejecuta JavaScript en Plugin API de otra que solo entrega contexto. No deduzcas un endpoint o un ejecutable a partir del nombre de una herramienta del editor.
2. Si el entorno dispone del adaptador de Codex, comprueba sus herramientas antes de usar bridge. Para capture necesitas una conexión directa autorizada; reutiliza una configuración existente si es compatible. El esquema determina tool.name, los argumentos y los parámetros adicionales; las credenciales dependen del servidor y pueden no ser necesarias. Si no tienes esa configuración, solicítala sin pedir secretos en el chat.
3. Tras la revisión y autorización del usuario, ejecuta capture sobre el componente solicitado. La captura temporal es de solo lectura y no importa el componente. Comprueba el resultado y sus issues antes de usar save. Tener un esquema compatible no prueba que la conexión o la autenticación funcionen.
4. Si no hay transporte utilizable, informa NOT RUN y DS_GAP para esa importación. Si la configuración es incorrecta o la captura falla, identifica ese motivo concreto; no declares incompatible todo un editor ni reconstruyas la respuesta a mano.

La herramienta use_figma del conector de Codex expone code, fileKey y description; este esquema encaja con bridge. Su disponibilidad en Codex no acredita una conexión directa de Claude Code ni proporciona el CONFIG que necesita capture. La comprobación de Claude Code debe ejecutarse en ese entorno, con una conexión accesible y autorizada.

## Límites Del Transporte

El CLI consulta tools/list y comprueba que la herramienta declarada exista y exponga los argumentos configurados. El servidor debe ejecutar JavaScript en el contexto Plugin API de Figma: un MCP que solo entregue contexto de diseño no basta. codeArgument/fileKeyArgument permiten adaptar nombres sin modificar el núcleo. arguments añade parámetros exigidos por ese servidor. Para una herramienta que solo recibe código, configura explícitamente `"fileKeyArgument": null`: no se envía ese argumento y el código exige que figma.fileKey exista y coincida con el archivo solicitado. Si la API no permite comprobarlo, falla; no supone que el archivo activo sea el correcto. La portabilidad del cliente NO prueba que cualquier conexión MCP de Figma soporte el colector.

Si un servidor limita las respuestas, CONFIG admite chunkSize entre 1 y 12000: captura fragmentada explícita, hasta 128 bloques. Cada bloque relee todo; se comparan offsets, total y checksum, sin mezclar capturas. Ni una llamada completa ni los bloques son una lectura atómica fijada a una revisión de Figma. timeoutMs limita cada petición entre 1000 y 300000 ms. Errores, truncamientos y herramientas inaccesibles fallan sin éxito parcial. Un nuevo intento crea siempre OTRA sesión. capture elimina su propia sesión fallida por defecto; --keep-failed la conserva para diagnóstico y muestra su ruta. Las sesiones exitosas se conservan hasta guardarlas; elimina después únicamente esa sesión temporal, no otros directorios. Nunca copies respuestas manualmente para eludir un fallo.

Las pruebas stdio ejecutan el CLI con un servidor MCP real de prueba y una respuesta superior a 12000 caracteres; las HTTP usan un servidor de prueba en loopback. Verifican transporte y persistencia sin APIs del editor. No equivalen a una prueba de autenticación o de Plugin API contra un servidor Figma concreto: comprueba esa conexión en el entorno de importación antes de prometer soporte.

Úsalo solo si ese orquestador y sus herramientas existen, transfiriendo stdout programáticamente. No es requisito del contrato ni una vía disponible automáticamente en Claude Code. A diferencia de capture, este adaptador conserva las sesiones fallidas y muestra su ruta para diagnóstico; elimina únicamente esa sesión cuando deje de ser necesaria. scripts/lib/capture-bridge.mjs también acepta adaptadores runFigma/getCode/stage.

Esa validación solo acredita la conexión probada, no todos los editores o servidores.

## Persistencia Y Contrato

Toda entrada del mapa exige evidence. No hay política externa, excepciones, migración automática ni avisos que sustituyan una captura: ficha sin evidence es FAIL en ambos verificadores. Los fixtures también enlazan snapshots válidos y comprueban los avisos sin filtrarlos.

Tras un diagnóstico permitido, ejecuta `node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs save . --chunks-dir DIRECTORIO_TEMPORAL`. Guarda literalmente snapshot/hash devueltos. save no importa componentes, cambia relaciones ni elimina capturas anteriores. Las órdenes de bajo nivel code, stage, validate-session y session sirven para adaptadores: `node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs session` crea un directorio único. stage usa wx deliberadamente: EEXIST exige otra sesión. Si ningún transporte es operativo, informa NOT RUN y DS_GAP para la importación antes de escribir; no relajes la evidencia.

## Captura v2

capture exige schemaVersion=2 y source.collector=capture-figma-v2. El perfil añade absoluteBoundingBox y absoluteTransform, capturados directamente como caja absoluta y matriz 2x3. Null/lecturas fallidas no autorizan geometría inventada. La matriz absoluta evita multiplicar relativeTransform siguiendo parentId sin respetar las particularidades de grupos/booleanos. absoluteRenderBounds, geometría vectorial y bytes de imagen quedan fuera. Se exige recapturar v1, sin alterar evidencia histórica para simular una captura v2.

Ruta: `design-system/figma/snapshots/FILE_KEY/NODE_ID_CON_GUION/SHA256.json`, fuera de las carpetas de componentes, que conservan metadata.json y usage.md. El kit vacío no trae snapshots.

El sobre contiene schemaVersion=1, capturedAt, hash y capture. SHA-256 cubre el JSON canónico de capture, no capturedAt: claves ordenadas, arrays preservados, números sin redondear. Identifica contenido, no revisión, vigencia ni autenticidad. source.revision es null porque el colector no obtiene revisión.

Antes de buscar el nodo, el colector comprueba `figma.skipInvisibleInstanceChildren` y lo desactiva durante toda la captura: así incluye descendientes ocultos de instancias también en Dev Mode. Restaura su valor anterior en `finally`, tanto tras éxito como tras fallo; no cambia la visibilidad de ninguna capa. Si no puede verificar, desactivar o restaurar ese filtro, la captura falla en lugar de declarar un recorrido completo. Los snapshots anteriores no demuestran que se controlara ese filtro; si su captura se ejecutó con él activo o no puede verificarse, repite la captura antes de afirmar cobertura de descendientes ocultos, sin reemplazar evidencia histórica ni actualizar el componente sin autorización.

- source: herramienta, API, versión del colector, fileKey, nodo solicitado y raíz resuelta.
- profile: campos consultados, campos de segmentos, alcance y exclusiones.
- nodes: identidad, padre, tipo, nombre, hijos, propiedades brutas, inspected y notApplicable. Incluye ocultos y descendientes de instancias; conserva mainComponent accesible. notApplicable indica ausencia del campo en la API, no interpretación semántica.
- observations: ID `nodeId#field#kind`, nodo, campo, kind property/binding/style, valor bruto y variableId/styleId. Segmentos conservan start/end; figma.mixed es `{ "mixed": true }`.
- variants: todos los componentes hijos del set y sus propiedades.
- collections: identidades, modos, modo predeterminado e IDs de variables.
- variables: valores brutos usados y destinos de alias en todos los modos. NO sustituye el inventario file-level: excluye valores de variables no usadas.
- styles: definiciones aplicadas accesibles, no prueba del origen de cada propiedad.
- coverage: recorrido, nodos e issues. Excluye geometría vectorial y bytes de imagen. Lectura fallida no equivale a ausencia.

## Decisiones Y Cobertura

evidence guarda snapshot, hash, decisions, textDimensions, translations y dispositions. Cada binding/literal enlaza observation; nodo y figmaProperty coinciden. approximate conserva `figmaValue: { source: "PLUGIN", field, value }` con field y value idénticos a la observación, incluidos objetos con unidad; `figmaValue.unit` no está permitido. El nombre de la herramienta se registra en la procedencia del snapshot, no en ese source. Comprobar el dato bruto no demuestra equivalencia CSS ni sustituye la comparación renderizada. Campos fuera del perfil requieren ampliar y versionar el colector con pruebas.

`node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs dimensions SNAPSHOT` verifica el hash y devuelve requisitos deterministas para cada `width`/`height` observado de nodos TEXT, sin escribir ni cambiar el perfil de captura. `textDimensions` debe contener un registro por requisito, con `{ observation, behavior, rule, observations, treatment }`. No hay compatibilidad para fichas que omitan este array; en un componente sin dimensiones de texto sigue siendo obligatorio como `[]`.

`text-auto-resize-v1` clasifica WIDTH_AND_HEIGHT como content en ambas dimensiones; HEIGHT como fixed en ancho y content en alto; NONE/TRUNCATE como fixed en ambas. La presencia de FILL o un sizing distinto de FIXED/HUG en esa dimensión, un valor dimensional no numérico, un auto-resize ausente/no admitido o un binding que interfiera con sizing intrínseco deja el comportamiento unknown. El array observations conserva exactamente las refs de auto-resize, sizing y bindings dimensionales presentes que devuelve el comando. No adivina alineación del nodo, constraints ni una traducción CSS por el nombre de una capa.

Un tratamiento declaration requiere fixed y un binding/literal de esa dimensión con el mismo destino CSS; translation exige selector, propiedad dimensional y una entrada translations que incluya la dimensión y las refs de apoyo; delegation exige pertenecer a los descendientes de una instancia mapped validada con su configuración; unresolved solo admite unknown y una entrada `unresolved` explícita, con field `textDimensions.<observation>`, motivo, fuente y blocking false. La incertidumbre esencial sigue causando DS_GAP, no un unresolved no bloqueante. Los destinos dimensionales son width/inline-size y height/block-size. No admite excluir dimensiones capturadas por estar ocultas. Los literales que congelan dimensiones content fallan aunque coincidan con la medida de ejemplo o se llamen approximate.

El resultado aparece en review.textDimensions y conserva NOT VERIFIED para comportamiento CSS y renderizado. Estos requisitos solo cubren dimensiones de texto, no todas las propiedades visuales. Una traducción enlazada sigue siendo una decisión pendiente de comprobar, no evidencia de implementación correcta. El contrato dimensional se conserva; el perfil geométrico v2 exige recapturar las importaciones anteriores.

decisions contiene `{ target, rule, reason, observations }`. target es `variantClassification.Eje.Valor` o `notBuilt[indice]`, único y existente. Cada clasificación y notBuilt necesita decisión. Se validan referencias y condiciones de reglas conocidas, no calidad del argumento. Las decisiones manuales generan un aviso agrupado de justificación NOT VERIFIED, con detalle en review.manualDecisions. reason no demuestra una decisión correcta.

translations contiene `{ observations, cssSelector, cssProperty, reason }` para traducciones compuestas. dispositions contiene `{ observations, kind, reason }`, kind excluded/deferred/delegated. Agrupa IDs cuando corresponda. Ambas necesitan revisión, no prueban fidelidad CSS y no rescatan omisiones esenciales.

Para un componente mapped admite una disposition `{ kind: "delegated", instance, resolvedComponent, configuration, reason, differences: [] }`. instance es la ref Figma; configuration copia exactamente componentProperties capturado. El check exige principal identificado en el mapa (clave de entrada, figma.refs o figma.variants), configuración idéntica y una captura sellada del componente reutilizado para comparar. Layout y tamaño de la instancia siguen a cargo del padre. No delegues external o identidades dudosas.

review.delegationDifferences conserva resultados derivados por propiedad: same, difference, unmatched, unreadable o not applicable. El sufijo del ID no basta: se comprueban principal, clave si está disponible, archivo de origen, tipo/nombre y estructura ordenada de descendientes. Se comparan ligaduras por identidad y propiedades de fills/strokes; los colores resueltos requieren modos equivalentes legibles. Pinturas múltiples cambiadas/reordenadas y anidados dentro de anidados quedan unmatched; datos mixed/unavailable o lecturas fallidas quedan unreadable, nunca igualdad. Los índices no demuestran identidad de pintura. No se atribuye cuándo ni cómo surgió una diferencia.

Cada difference exige en differences `{ id, treatment: "implemented", part, cssProperty, reason }` o `{ id, treatment: "omitted", reason }`. Copia el id derivado, no un estado de verificación escrito por el agente. IDs repetidos, obsoletos o desconocidos fallan. La cobertura de bindings/estilos descendientes no acredita implementación: una diferencia sin declarar es error; omitted, unmatched y unreadable bloquean confirmed. La plantilla conserva dispositions vacío si no hay delegaciones.

Distingue el elemento que suministra un valor del que lo consume para pintar. No declares una propiedad del envoltorio como destino de pintura si esta ocurre dentro del componente delegado: background-color del envoltorio no representa el background-color del elemento interior que usa una máscara. Describe en reason el mecanismo realmente implementado (variable CSS, prop del hijo, currentColor u otro), sin imponer una API. Medir una variable CSS suministrada por el padre no demuestra que el hijo la herede, la consuma ni que no la sobrescriba; conserva la verificación pendiente. Si el formato actual no permite expresar fielmente el destino delegado, no inventes un part/cssProperty aproximado ni marques una declaración como implemented solo para satisfacer el check: informa de la limitación y mantén bloqueada la confirmación. Tampoco declares omitted una implementación existente solo porque no puedas representarla. Verificar suministro, consumo y pintado es una ampliación posterior; esta nota no añade campos ni comparadores.

En fidelity cada diferencia implementada genera un check delegation NOT COMPARABLE: todavía no hay comparador automático de valores CSS y exige checkReview específico con artefactos del mismo caso. Omitted genera NOT RUN (implementación pendiente, no fallo del navegador ni orden de reintentar). Ninguna revisión general ni texto libre rescata omisiones o correspondencias sin resolver. El hash semántico por caso y sus archivos examinados incluyen el snapshot verificado completo del hijo, conservadoramente. Cambios de cualquiera de las dos capturas, correspondencia, tratamiento o reglas caducan las confirmaciones afectadas; los motivos solos no cambian la validez. Se reutilizan COMPARATOR_VERSION y su huella, sin versionado paralelo. No cambia el perfil ni la persistencia del colector; no se exige recaptura por un cambio de formato del snapshot.

nextActions distingue DECLARE_DELEGATION_TREATMENT, IMPLEMENT_DELEGATION_DIFFERENCE, REVIEW_DELEGATION_DIFFERENCE, RESOLVE_DELEGATION_CORRESPONDENCE e INSPECT_DELEGATION_READ_FAILURE. Una lectura fallida exige revisar motivo, permisos y soporte del colector; recaptura solo si puede resolverla. Una declaración stroke → background-color de una máscara no prueba el color renderizado.

En verify:imports, REVIEW_DELEGATION_DIFFERENCE solo se solicita si falta una confirmación vigente en alguno de los casos de fidelidad que contienen la instancia, o si no hay un caso que la cubra. Las confirmaciones se revalidan antes de filtrar: una revisión caducada o de otro caso no elimina la acción. El diagnóstico temporal no acredita esas revisiones y conserva sus acciones.

Para componentes remotos, la clave del principal puede establecer identidad del componente, pero el perfil actual no captura claves estables de variables/colecciones entre archivos: IDs de variable o modo iguales en dos files no acreditan identidad. Esas comparaciones quedan unmatched, no same. La presencia/ausencia legible de una ligadura sigue siendo un hecho distinto de su identidad.

## Verificación Y Comparación

El lector distingue captura vacía (sin nodos), incompatible (esquema/perfil), corrupta (JSON, sello o estructura incoherentes) e ilegible (archivo ausente, permisos o lectura). El gate y finalize:import conservan importDiagnostics/nextActions aun si el preflight bloquea la recogida. No hay autenticación del productor: un nombre de herramienta o un hash no prueban que se ejecutara. Ante evidencia histórica dañada o ausente, inspecciona y restaura sus bytes originales desde una copia fiable o Git; no corrijas el hash ni rellenes el árbol a mano. Si hace falta recapturar, revisa y autoriza el transporte, crea una sesión nueva, guarda explícitamente en una ruta nueva y revalida la ficha. Ninguna acción añade --approve-connection ni autoriza escritura. Una referencia insegura requiere revisión de la ruta antes de cualquier recuperación.

La captura Figma usa el perfil v2. El comparador y el productor de mediciones tienen versiones independientes y huellas de sus declaraciones/dependencias locales relevantes. Los cuerpos y recibos originales requieren measurementVersion idéntica; una versión anterior caduca la evidencia y una discrepancia interna es error. No se necesita recapturar Figma solo por cambiar reglas del navegador. Los informes de comparación v4 usan huella semántica por caso, medida original del navegador y captura Figma PNG tipadas; no aceptan archivos arbitrarios como evidencia renderizada. Todo caso behavior asociado por baseline exige su medición publicada y checks en PASS antes de confirmed, sin rescate manual; sus cambios caducan la confirmación. apply valida la propuesta en memoria antes de publicar metadata. Ni ese gate ni hashes/artefactos tipados autentican una valoración visual. El CSS intrínseco contempla especializaciones y pares físicos/lógicos, manteniendo revisión para ámbitos inciertos.

verify-ds comparte las capturas y los resultados de evidencia con el check de planes en la misma ejecución, sin caché global ni comprobación duplicada. El arranque de una vista independiente vuelve a verificar: no hereda un PASS anterior. Las traducciones generan un único aviso y detalle en review.translations. Los requisitos deterministas y fuentes agrupadas se obtienen con scripts/verification-plan.mjs, sin modificar el perfil del colector. Confirmaciones de usage se contrastan por caseId, configuración, informe y hashes; esto no autentica el juicio renderizado.

La ficha exige además verification con recursos y casos reproducibles. `node .agents/checks/verify-render-plan.mjs .`, integrado en verify-ds, comprueba cobertura de tipografía esencial y recursos observados sin cambiar el snapshot. La vista temporal `scripts/verification-preview.mjs` conserva medidas originales y hashes, siempre NOT VERIFIED hasta revisión independiente. Un hash, una fuente disponible o un caso de comportamiento no confirman fidelidad.

`node .agents/checks/verify-figma-evidence.mjs .` compara primero con SU snapshot: hash, perfil, grafo, variantes, partes, bindings, modos explícitos, estilos, datos brutos, dimensiones de texto y conversiones directas limitadas. Detecta bindings/estilos sin contabilizar y dimensiones TEXT sin cobertura o con comportamiento contradictorio. Las demás propiedades no referenciadas se cuentan, sin presuponer que todas deban convertirse en CSS. Avisos de literales agrupados, con detalle en review.literals. verify-ds incluye errores y avisos. Ninguno prueba completitud de Figma vivo ni equivalencia visual.

Reglas concretas de ese check:

- Los requisitos de cobertura se derivan de lo observado, así que un campo que no se pudo leer eliminaría su propio requisito. Por eso una lectura fallida (`coverage.issues`) o un valor `{ "unavailable": true }` en un campo esencial es un error de captura, no una ausencia: tipografía, `fontName`, `characters`, `segments`, tamaño y `layoutSizing*` de nodos de texto; `variantProperties` de cada variante; `componentProperties` de cada instancia; y `explicitVariableModes`/`resolvedVariableModes` de los nodos que usan variables. Se resuelve capturando de nuevo o informando `DS_GAP`. Las lecturas que otro check ya trata como desconocidas (trazos, bounds, transformaciones, modos de la raíz) siguen siendo `NOT COMPARABLE`, no error.
- `variants` y `variantClassification` se contrastan con los ejes y valores de las variantes capturadas: un eje o valor ausente del snapshot, o un valor capturado sin clasificar, es error. Un eje inventado no se salva con una decisión `manual`.
- Un valor `{ "mixed": true }` o `{ "unavailable": true }` no puede registrarse como literal, ni `direct` ni `approximate`. Los campos de segmentos de texto (`segments[n].campo`) se comparan igual que los del nodo.
- Un binding cubre a sus descendientes por `.` y por `[`: un literal sobre `fills` no puede sustituir a `fills[0].color`.
- Si el propio nodo fuerza un modo para la colección de la variable (`explicitVariableModes`), el binding debe declarar `modeOverride` con el mismo modo. Un modo no declarado por el nodo, pero no predeterminado, no es error, porque el contrato solo pide `modeOverride` al nodo que lo fuerza: genera un aviso agrupado. Cubre un ancestro capturado que lo fuerza y también un modo heredado de fuera del subárbol capturado, visible solo en `resolvedVariableModes` frente al modo predeterminado de la colección. El aviso muestra nodo, variable, colección y modos resuelto y predeterminado, con nombres e IDs. review.inheritedModes conserva ese detalle y el ancestro capturado más próximo que fuerza el modo, cuando existe. Un modo resuelto no disponible se representa como null, sin deducirlo del ancestro. La fidelidad queda NOT VERIFIED hasta comprobar que se reproduce el modo requerido por Figma; el aviso no se convierte en error.

`node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs propose SNAPSHOT` propone por valor. browser-interaction-v1 exige State=Hover/Pressed y propone interacción interna, pendiente de confirmar semántica. No adivina booleanos, Disabled ni API. Otros casos quedan ambiguous. Ambigüedad que cambia la API exige criterio; duda no bloqueante se registra y queda NOT VERIFIED.

`node .agents/skills/create-ds-from-figma/scripts/figma-capture.mjs compare ANTES DESPUES` compara capturas del mismo origen y raíz, después del check de importación, sin modificar nada. Una diferencia no demuestra revisión nueva ni error histórico; una lectura no autoriza actualizar componentes.
