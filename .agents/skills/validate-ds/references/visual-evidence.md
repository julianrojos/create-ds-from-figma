## Visual comparison

Compare position and shape independently: a shape review cannot override an AABB-center position FAIL. Comparator fingerprints follow relevant named local dependencies (including requirements/dimension rules); producer fingerprints independently cover browser collection and raw-value conversions. Original body/receipt measurementVersion values must match; old rules stale confirmations, while missing/mismatched versions invalidate the record even when stale. Recollect rather than relabel original bytes. The version-keyed executable-rule fingerprint test enforces a reviewed comparatorVersion increment for rule/tolerance edits (excluding diagnostic prose). Comparator rule/tolerance changes require a comparatorVersion increment and make earlier confirmations stale. Wording changes in reason/scope are not factual differences; values, deltas, IDs, statuses and tolerances remain checked. Behavior invariants require explicit expectations and the matching baseline measurement when applicable; record their results separately without claiming new Figma variants, but require every associated behavior check in PASS before confirmed. A general visual review cannot rescue noncomparable or unexecuted mandatory behavior. Keep candidate/NOT VERIFIED for those obligations without claiming a demonstrated visual defect.

Confirmation reports use schemaVersion 4. Retain original browser-measurement JSON with its published original receipt and a Figma PNG under design-system/verification/artifacts. PNG decoding checks CRC and derives image width/height; they must stay within 1 px of the captured node bounds times the declared scale (WITHIN_ONE_PIXEL_OF_NODE_BOUNDS), a tolerance that does not assume Figma's fractional export rounding. If the captured size is unreadable, dimensionComparison stays NOT VERIFIED. A matching size does not show that the image depicts the node. Scope/scale remain reviewer declarations, not proof of authenticity or fidelity. Review that the image depicts the complete intended node/configuration. The reviewer still supplies the comparison judgment. Both publish and report require mapped component CSS even outside src/. Local src/public/token files, Figma relationships, manifests, locks and Vite/TypeScript configurations are hashed conservatively; include other examined inputs explicitly. Installed node_modules, remote resources, system fonts and browser changes remain outside that closure. Metadata staleness uses the relevant per-case semantic fingerprint; its full hash is historical audit data.

When persistent writes are authorized, publish a measurement with `node .agents/skills/create-ds-from-figma/scripts/verification-plan.mjs publish . METADATA CASE RECEIPT`. It validates original receipt/body hashes, unchanged inputs and viewport, preserves both byte streams and verifies destination hashes. Use its returned artifact in REVIEW; do not transcribe values. Publication never supplies PASS or authenticity. Standalone validation does not authorize publication.

For an authorized confirmed entry after a real rendered comparison, use `node .agents/skills/create-ds-from-figma/scripts/verification-plan.mjs report . METADATA CASE REVIEW`. Review supplies the explicit rendered judgment, revision IDs/unavailability reasons, retained original artifacts and behaviors: [{ caseId, artifact }] for every behavior linked by baseline (or []); each artifact is the published original browser measurement. The producer compares these measurements against the retained fidelity baseline and requires all checks PASS; the script derives configuration and input/artifact hashes. It does not perform the comparison, certify authenticity or promote a measurement receipt. A standalone validation does not authorize writing this persistent report or usage.md.

For a component imported from Figma, start the project with `npm run dev` and compare the implemented component in a browser with screenshots of the exact Figma component or variant nodes listed in its map. If `App.tsx` shows another component, use a temporary preview harness and remove it after the check; do not overwrite the user's app. Use the same visible label/content, size and applicable collection-mode configuration on both sides. Cover each distinct visual treatment and size, including default, hover, disabled and optional content where Figma provides them. Trigger interactive states in the browser; do not infer hover from a static default screenshot. Compare geometry, spacing, typography, colors and assets; report differences and propose corrections. Correct them only when implementation changes are authorized, and rerun the affected comparison before claiming PASS. Record the compared Figma refs, browser URL or screenshots, active modes, states covered and any remaining mismatch. Figma does not define an unobserved focus style: check keyboard focus visibility under Accessibility instead of claiming a Figma visual match.

If Figma or a browser is unavailable, report this check as NOT RUN with the reason and Overall as NOT VERIFIED. Do not silently treat the comparison as irrelevant for an imported visual component.
