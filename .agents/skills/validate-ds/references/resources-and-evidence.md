## Resource Diagnostics

Resource inspection must revalidate current policy authorization as well as file
bytes. Revoked/stale provenance is INVALID, with RECHECK_REGISTERED_SOURCES issues;
if the cases need the resource, it remains an essential gap. Inspection is read-only:
re-evaluation and explicit registration belong to an authorized import/update.

Composition screenshot, storage, decoding, unexpected browser and restoration errors are NOT RUN, not unsupported-condition abstentions. Retain their reasons and any partial artifacts; a group with failed restoration cannot retain passing checks. Explicit comparability/budget conditions remain NOT COMPARABLE. Follow the retry action without treating execution failure as a visual mismatch.

Composition NOT RUN fails the temporary diagnosis and yields RETRY_COMPOSITION_DIAGNOSTICS with case/check/reason and a retry command, not a visual-difference claim. NOT COMPARABLE remains abstention. nonOpaque counts pixels without stable opaque ink; opaque pixels in excluded regions remain indeterminate. temporary-read means reading existing temporary artifacts only; retry requires project-read/browser-execution/temporary-write. Action permissions are informational prerequisites, never automatic authorization. None of these diagnostic changes affect published confirmations.

The temporary --diagnose result also exposes diagnostics.compositionSummary and cases[].composition. Inspect REVIEW_COMPOSITION_DIAGNOSTICS and its retained composed/isolated screenshots: the experimental model compares distinguishable opaque ink of uniquely mapped sibling leaf shapes using captured source order (including reversed auto-layout). It does not prescribe DOM order. Ambiguity, text, translucent paint, effects or isolation changes are NOT COMPARABLE. PASS covers sampled ink only, not source masks/blend operations absent from the snapshot or overall visual fidelity. It is not a published measurement, confirmation check or replacement for visual reviews. Never claim that a contour is visible from geometry alone.

For temporary feedback on existing code use `npm run finalize:import -- ROOT METADATA --diagnose` under INV-DIAGNOSE/INV-PREWRITE in AGENTS.md. Read import-diagnose before executing and import-diagnose-results after receiving its output. The canonical process contract forbids publication/confirmation and preserves the independent application checks; missing execution remains NOT RUN.

For a read-only resource diagnosis use `node .agents/skills/create-ds-from-figma/scripts/verification-resources.mjs inspect ROOT METADATA`. Registration checks existing file bytes/hashes. Configuration is DECLARED only for a supported unconditional @font-face linking the registered file and matching descriptors through the explicit/static CSS entries described below; otherwise NOT VERIFIED. Loading remains NOT RUN. Inspect configurationWarnings and REVIEW_FONT_CONFIGURATION; the gate exposes fontConfiguration diagnostically. This is declaration linkage, not source selection, glyph identity, licensing or complete CSS validation. Unresolved/conditional imports need independent review. Essential unresolved sources or unloaded faces still block confirmation despite static warnings; diagnostic collection does not waive that gate. Snapshot-only requirements list candidates with pending cases/CSS, not essential gaps. Shared nextActions are prerequisites and argv, not authorization or shell strings. Never add --replace automatically. Source registration writes metadata and is outside standalone validation's read-only scope; authorized registration changes only existing source fields, never stylesheets or CSS, and does not confirm a correspondence.

Static font discovery also follows component JavaScript/TypeScript static imports/reexports and resolvable installed CSS package subpaths without executing project code. All queried imports (?) remain NOT VERIFIED, including worker/sharedworker, cache queries and CSS @import. The shared exports resolver uses the pinned resolve.exports dependency, not Node require conditions: it requires one stable CSS target across unresolved browser/module/mode conditions (also optional style for CSS imports), preserves exclusions/key order, and never falls back around a blocked exports path. Unknown conditions, ambiguous destinations, browser remapping, dynamic imports, conditional CSS and package JavaScript side effects require independent review. This conservative scope is not arbitrary project plugin/alias resolution. Stylesheet discovery never treats audited inputs alone as loaded. Missing CSS entry points, failed component CSS imports and undecodable essential fonts must not complete browser verification; real-browser regressions exercise these paths. Shared analyzer edits version the comparator and stale older confirmations, without relabeling measurements or changing the measurement producer version.

Resource actions retain metadata paths in targets when the gate/finalizer deduplicates equivalent obligations. Do not merge different commands/resources or lose a component's obligations. Font configuration warnings also appear in gate warnings with a component prefix; they remain diagnostic. A recorded css.weight must request one numeric weight from 1 to 1000, normal or bold, as a string. Ranges are available face descriptors only, not requested weights; invalid requests fail plan validation and source registration before writing.

## Captured evidence

Verification commands run locally; no CI or Git hooks are configured. Collection automatically requests an available preview port; finalize:import --collect accepts --port for an explicit port and refuses an occupied one. collection.preview records effective URLs/port; the adapter closes its preview on completion. Do not use a local-only branch/commit anecdote as a reproducible kit guarantee: regression fixtures are versioned, but do not prove real Figma fidelity.

Application diagnostics are required for a root index.html or an App/app/main/index JS/TS entry under src; application.signals records the detected files. They scan source literals under src without running project code, including custom-named demos. No signals means an explicitly scoped NOT APPLICABLE, not proof that an arbitrary project has no UI. Finalization rejects its target usage.md as an examined input, including extra reviewer or behavior inputs, before publishing reports: rewriting that file must not stale the confirmation itself. AABB size diagnostics have their own nonblocking threshold, independent of position/fidelity tolerances.

Within an authorized import or explicit recording request, `npm run finalize:import -- ROOT METADATA --reviews REVIEW_FILE` records supplied rendered reviews, generates immutable reports, validates their currency and atomically updates only the canonical correspondence JSON before running the repository gate. REVIEW_FILE has schemaVersion 1 and cases [{caseId, review}], covering every fidelity case with the existing report-review contract. It never supplies its own PASS. `--collect` collects/publishes with the locked runtime; `--check` is read-only. Collection and recording are not authorized by standalone read-only validation. Closure retains static CSS border warnings and informational AABB size deltas; these are not objective shape failures for noncomparable vectors.

For import delivery, run `npm run verify:imports` as a read-only repository gate. It consumes verify-ds visual summaries and revalidates persisted confirmations, including mandatory behavior and essential resources, without remeasuring geometry. Candidates, missing fidelity cases/summaries, stale reports and unestablished correspondences fail. Application literal diagnostics run independently in a blank page of the kit's locked Chromium, even if component preflight fails; no Vite or project code executes. Missing runtime is explicit NOT RUN and fails delivery. Prepare the runtime with `npm run test:browser:setup` only with installation authorization. This gate does not replace manual/rendered validation or prove overall visual fidelity.

Account for every node in each fidelity subtree, including structural containers. verification.nodeCoverage may use only verified same-layout-box/permanently-hidden conditions or an explicit unresolved obligation. Delegated instance internals do not waive mapping the instance placement. An omitted node fails; unresolved stays NOT RUN and cannot be rescued by a generic review. The capture profile is unchanged.

The original measurement includes cssDiagnostics with CSS.supports results for the exact literal declarations derived from component dependencies; reports and closure recompute those IDs. Missing/unsupported literal results block confirmation. Custom properties and var()/env() are outside this syntax lane, not implicitly validated. PostCSS border-default warnings require cascade review, not a universal prohibition. Application-wide diagnostics at the preview's diagnosticsUrl include App.tsx separately; do not mix their scope with component closure. Numeric/dynamic inline styles still need independent review.

An optional verification-browser.mjs import adapter uses an explicitly supplied Playwright module and browser executable without installing them. This is separate from the kit's mandatory locked real-browser test runtime. It publishes measurements and therefore is not authorized by standalone read-only validation; use the environment browser unless publication is separately authorized. It does not infer interactions or issue visual judgments. Typography calibration loads explicitly provided font files only in the calibration browser and records hashes/metrics; this is not proof of the Figma font binary or a universal tolerance policy.

TEXT geometry uses a provisional 1px threshold: numerical PASS requires a specific rendered checkReviews entry for geometry:PART, with artifacts of the same case, before measured/confirmed. This is an additional review obligation alongside fidelity NOT COMPARABLE reviews, not an exception to FAIL/NOT RUN or mandatory behavior PASS. General visual approval is insufficient. A same-browser font repeatability corpus does not establish Figma calibration across fonts or renderers.

Read contextual CSS check statuses, not the raw supported boolean: inactive @supports declarations do not fail, and unsupported vendor extensions require fallback/target-engine review rather than a universal-invalidity claim. Numeric inline constants use React units; dynamic expressions still need review. A static closure failure retains missing-measurement obligations while leaving supplied measurements explicitly unevaluated; do not infer currency from their presence.

The optional adapter reserves an empty output directory before starting. Static preflight failure retains structured closure/pending data and exits 1 without opening a browser; infrastructure failure retains execution phase/reason and exits 2. Read closure and application diagnostics, not execution COMPLETED alone, to assess completion. Publication still requires separate authorization for read-only validation.

Use verification-browser.mjs inspect-lock DIRECTORY for read-only reservation diagnostics. The default adapter output is a fresh temporary directory.

Exact source geometry applies only to fidelity. Supported vector/rotated 2D parts also get independent center-position checks; their shape remains NOT COMPARABLE. Behavior uses explicit containment/anchoring/centering/dimensional relations and, where required, a separately measured fidelity baseline. Unknown contexts remain NOT COMPARABLE. Hidden content may remain in the DOM. Essential visible-text fonts require current source files and loaded matching faces, not document.fonts.check alone. A loaded face does not prove glyph coverage. FAIL/NOT RUN block confirmed; specific checkReviews cover fidelity NOT COMPARABLE and provisional TEXT geometry PASS with exact retained artifacts, in addition to the general visual judgment. Diagnostics may still be persisted/published without a confirmation. Report static conformance separately from the VISUAL accounting and automatic check statuses; do not promote missing comparisons into PASS.

Run `node .agents/checks/verify-figma-evidence.mjs .` and read the component's required immutable `metadata.evidence.snapshot`. Missing evidence is FAIL, without exceptions. Capture issues, manual decisions, composite translations and delegated overrides remain NOT VERIFIED pending review. Detailed grouped findings are in each component's review report. This checks accounting against the import capture, not live completeness or rendering. Optional rereads do not authorize updates.
